# Q-L2-11 claim — constant-indexed instance boundaries

- Provider: Codex delegated subtask
- Claimed: 2026-10-13
- Starting commit: `6698ecf`
- Owned paths: `tools/sflc/tests/test_instance_array_boundaries.py`, this claim record.
- Scope: standard-library tests against the public compiler API using temporary
  SFL+ source files. No compiler implementation or shared runner changes.
- Status: complete; tests pass.

## Results

- The standalone suite has nine tests and runs with
  `PYTHONDONTWRITEBYTECODE=1 python3 tools/sflc/tests/test_instance_array_boundaries.py`;
  all nine pass. It writes tiny inputs under the system temporary directory and
  calls `sflc.translate` directly.
- Exact declared-instance boundaries behave as follows: a missing generated
  element raises `NameError`; a negative index raises `ValueError`; mixed
  suffix widths raise `ValueError` as ambiguous; and a runtime index raises
  `NotImplementedError` as nonconstant. `node[10]` maps to `node_0A` when
  declarations use two-digit uppercase hexadecimal suffixes.
- A declared memory remains an ordinary indexed memory read. With a scalar
  called `s` beside an instance `s_0`, bare `s[0]` raises
  `NotImplementedError: index of non-memory`, while the method-qualified
  `s[0].con(d).q` resolves to `s_0` (see follow-up correction below).
- The form `ch[i].con(d).q` inside an `any` generator is supported and expands
  across the declared `ch_00` and `ch_01` instances. A method-qualified
  `s[0].con(d).q` beside a scalar selector `s` resolves to the
  declared `s_0`; the test verifies the generated component connection and
  output alias. Bare `s[0]` remains ordinary indexing and raises
  `NotImplementedError: index of non-memory`. The nearby unsupported boundary
  is a second method call on the prior result, for example
  `ch[0].con(d).q.con(d).q`, which raises
  `NotImplementedError: nested call result`.
- The routing expectation checks that index 10 selects the alias for `node_0A`.
  Its in-test deliberate mutation changes the generated assignment to the
  `node_00` alias and confirms that the original expectation no longer matches.
- No compiler source or shared runner was changed. No real design source was
  modified or blanked, and no native-equivalence claim is made.

## Follow-up correction

After the initial result commit, the compiler owner added contextual
method-qualified instance resolution in the shared worktree. The scalar-name
collision case now correctly maps `s[0].con(d).q` to declared `s_0`; the test
was updated to assert that routing while retaining the bare `s[0]` rejection.
The standalone suite passes 9/9 against that compiler change. This follow-up
changes only this test and claim record; the compiler change is owned elsewhere.
